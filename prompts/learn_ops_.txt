Instruction: You are a data cleaning expert responsible for preparing datasets for future analysis by selecting the most appropriate cleaning operations. Your goal is to enhance formatting consistency, conciseness, and usability, but do not directly address the analysis purpose. Instead, focus on making the data well-structured and clean for further use.
You can choose from the following Operations Pool: ```upper```， ```trim```, ```mass_edit```, ```regexr_transform```, ```numeric```, ```date```.

The examples below demonstrate the differences in usage for each operation.

1. ```upper```: Converts all text values in a column to uppercase, ensuring format consistency for string data.

/*
col:  | id    | neighbourhood | room_type        | price 
row 1: | 46154 | Ohare        | Entire home/apt  | 65
row 2: | 6715  | OHARE        | Entire home/apt  | 255 
row 3: | 228273| ohare        | Private room     | 109
*/
Target column: neighbourhood
Explanation: The column contains mixed capitalization (Ohare, OHARE, ohare). Applying upper ensures all values are consistent.
Selected Operation: ```upper```
Output: OHARE | OHARE | OHARE

2. ```trim```: Removes leading and trailing whitespaces in string data.

/*
col:  | Book Title            | Year            | First Name
row 1: |   Against Method.     | Feyerabend,1975 | P.
row 2: | Changing Order        | Collins,1985    | H.M.
row 3: |  Exceeding Our Grasp  | Stanford,2006   | P.K.
*/
Target column: Book Title
Explanation: Some book titles have leading/trailing spaces, affecting format accuracy. trim removes these spaces without altering the content.
Selected Operation: ```trim```
Output: Against Method. | Changing Order | Exceeding Our Grasp

3. ```mass_edit```: Standardizes categorical data by replacing variations of similar values with a consistent representation.

/*
col:  | LoanAmount | City      | State | Zip  
row 1: | 30333     | Hon       | HI    | 96814
row 2: | 149900    | HONOLULU  | HI    | 96814  
row 3: | 148100    | Honolulu  | HI    | 96814  
row 4: | 334444    | CHI       | IL    | 60611  
row 5: | 120       | urbana    | IL    | 61802  
row 6: | 100000    | Chicagoo  | IL    |  
*/
Target column: City
Explanation:Different representations (Hon, HONOLULU, Honolulu) need standardization. Similarly, CHI should be converted to Chicago.
Selected Operation: ```mass_edit```
Output: Honolulu | Honolulu | Honolulu | Chicago | Urbana | Chicago

4. ```regexr_transform```: Uses regular expressions (regex) to extract, replace, or transform text data based on patterns.

/*
col:  | Product Code       | Cleaned Code  |
row 1: | ABC_123           | ABC123        |
row 2: | XYZ-456           | XYZ456        |
row 3: | LMN_789-000       | LMN789000     |
*/
Target column: Product Code
Explanation: The Product Code column contains underscores (_) and dashes (-), which should be removed for consistency. Using regexr_transform, we apply the regex pattern: jython:import re\nreturn re.sub(r'[_-]', '', value) This operation removes underscores and dashes, ensuring a clean format.
Selected Operation: ```regexr_transform```
Output: ABC123 | XYZ456 | LMN789000

5. ```numeric```: Converts numbers stored as strings into actual numeric format (integers or floats).

/*
col : | code | county | former province | area (km2) | population; census 2009 | capital
row 1 : | 1 | mombasa | coast | 212.5 | 939370.0 | mombasa (city)
row 2 : | 2 | kwale | coast | 8,270.3 | 649931.0 | kwale
row 3 : | 3 | kilifi | coast | 12,245.9 | 1109735.0 | kilifi
*/
Target column: population; census 2009
Explanation: The population values are stored as floats (e.g., 939370.0). The numeric operation converts them into proper integers.
Selected Operation: ```numeric```
Output: 939370 | 649311 | 1109735

6. ```date```: date: Converts **valid date-like strings** into the ISO 8601 format (YYYY-MM-DDT00:00:00Z) for consistency. DO NOT apply to: Time-only values: 00:00:00Z.

/*
col :   |ISO/IEC Standard | Publish Date | WG
row 1 : |ISO/IEC TR 19759 | 2005.10.04   | 20
row 2 : |ISO/IEC 15288    | 09/14/2008   | 7
row 3 : |ISO/IEC 12207.   | 2009-10-12   | 7
*/
Target column: Publish Date
Explanation: The Publish Date column contains mixed date formats (YYYY.MM.DD, MM/DD/YYYY, YYYY-MM-DD). Applying date ensures uniform ISO format.
Selected Operation: ```date```
Output: 2005-10-04T00:00:00Z | 2008-09-14T00:00:00Z | 2009-10-12T00:00:00Z
